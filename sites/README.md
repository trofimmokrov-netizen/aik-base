# AIK BASE — отдельный сервис команд для Sites

Подготовлен Fetch-обработчик команд Telegram. **Публикация ещё не выполнена**: в текущей сессии нет инструментов создания/развёртывания проектов Sites. Файлы не содержат ID проекта, домена сервиса или секретов. Не подставлять идентификатор проекта Ксении: это должен быть отдельный сервис.

## Что работает в обработчике

`/start`, `/services`, `/order`, `/contact`, `/help`, `/id` и кнопка мини-приложения по адресу https://trofimmokrov-netizen.github.io/aik-base/. Телефон берётся из общего `shared/site.json`. Ответы явно описывают ручную отправку заявок; произвольные сообщения не пересылаются мастеру. База, доступ к истории заказов, автоматические уведомления и оплата в этот сервис не входят. Основной сайт остаётся в статическом режиме.

Обработчик возвращает `sendMessage` непосредственно в ответ на webhook — это поддерживается Telegram Bot API. Поэтому во время обработки команды не требуется исходящий запрос с токеном. Результат доставки таким способом недоступен; повтор webhook может привести к повтору ответа. Обработчик не создаёт заказы и не меняет статусы.

## Проверенные команды

Из `/workspace/aik-base`, Node 24, зависимости из корневого lockfile:

```sh
npm run test:sites-bot
```

Команда собирает `dist/sites-bot/worker.mjs` и запускает тесты исходного и собранного Fetch-обработчиков. Файл сборки не содержит импортов Node, внешних модулей или секретов. Это готовый модуль обработчика, а не архив с подтверждённой платформенной конфигурацией Sites: проект и требуемую структуру публикации следует создать штатным инструментом Sites.

## Передача в сессию с инструментами Sites

1. Создать **новый** проект AIK BASE с серверным обработчиком; не изменять существующий проект `ksusha_epoxy_premium` или его секреты. Использовать `sites/bot.mjs` либо собранный ES-модуль как Fetch-обработчик в серверной точке входа, аналогично `bot/build/sites-worker.ts` проекта Ксении. Окончательную упаковку и привязку проекта выполнить средствами Sites, доступными в той сессии.
2. Через защищённые настройки Sites задать отдельный `TELEGRAM_WEBHOOK_SECRET`: случайная строка из 32–256 символов `A-Z`, `a-z`, `0-9`, `_`, `-`. Не вставлять секрет в исходники, аргументы инструментов, Git или переписку.
3. Развернуть сервис и получить **настоящий** HTTPS-адрес. `GET /health` должен возвращать `service: aik-base-telegram-bot`, `webhookConfigured: true`, `ordersMode: manual`. Это подтверждает конфигурацию, а не доставку сообщения.
4. Для регистрации webhook использовать токен AIK BASE из защищённого хранилища. Не использовать токен Ксении. Задать в защищённом окружении `TELEGRAM_BOT_TOKEN`, тот же `TELEGRAM_WEBHOOK_SECRET`, настоящий `PUBLIC_API_URL` и `MINI_APP_URL=https://trofimmokrov-netizen.github.io/aik-base/`, затем выполнить `npm run sites:connect`. Команда проверяет опубликованный `/health`, секрет webhook без отправки сообщения, HTML сайта и имя бота; только затем регистрирует команды, меню и webhook. После регистрации сверяет настройки через Telegram API. HTTPS proxy и системные CA поддерживаются; обновления не удаляются. Токен требуется для регистрации, хранить его на клиенте нельзя.
5. Проверить `getWebhookInfo`: настоящий URL и отсутствие новых ошибок. В Telegram вручную проверить `/start`, `/services`, `/contact`, открытие Mini App и честный текст `/order`. Наличие команды в меню само по себе не подтверждает обработку.

Webhook принимает только POST, секретный заголовок `X-Telegram-Bot-Api-Secret-Token`, JSON до 32 КиБ и корректный `update_id`. Группы и неподдерживаемые обновления игнорируются. Входящие данные и секреты не логируются. `/telegram/webhook` — дополнительный совместимый маршрут.

Документация Telegram: https://core.telegram.org/bots/api#making-requests-when-getting-updates

## Автоматическое подключение после публикации

В GitHub подготовлен workflow **Connect Telegram bot** (`.github/workflows/telegram-connect.yml`). Он запускает ту же проверенную команду из Actions без установки дополнительных зависимостей. Предварительно в защищённых настройках репозитория должны быть секреты `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` (совпадает с Sites) и переменная `SITES_BOT_URL` с настоящим корневым HTTPS-адресом сервиса. Затем запустить workflow вручную или через `gh workflow run telegram-connect.yml`. Для этого нужны права на Actions; в текущей среде запросы к настройкам секретов/переменных получают 403.

Workflow подключает **уже опубликованный** сервис: он не создаёт Sites-проект, не загружает туда новую версию кода и не заменяет платформенные инструменты публикации. Если сервис отсутствует или проверка не проходит, настройки Telegram не меняются. После успешной настройки проверка `/start` человеком подтверждает фактическую доставку, которую webhook-response сам проверить не может. Новая ошибка Telegram во время подключения завершает workflow неуспешно.
