# API и Telegram без VPS: Cloudflare Workers + D1

Реализован отдельный serverless backend: Cloudflare Worker обрабатывает API и webhook, D1 хранит заявки и очередь, Cron раз в минуту настраивает бота и повторяет доставку; новые ответы и уведомления отправляются в фоне сразу после сохранения. Арендовать и поддерживать VPS не требуется. У Cloudflare есть бесплатные тарифы с ограничениями запросов, CPU и базы; проверьте действующие квоты в своём аккаунте. Платные ресурсы и аккаунт автоматически не оформляются.

Публичный сайт пока остаётся статическим и работает как прежде. Он переключается на API только после успешной проверки настоящего backend и регистрации Telegram.

## 1. Что нужно для публикации

- Ваш аккаунт Cloudflare с активированным `workers.dev` в Workers & Pages.
- `CLOUDFLARE_ACCOUNT_ID` — Account ID из панели Cloudflare, 32 шестнадцатеричных символа.
- `CLOUDFLARE_API_TOKEN` — отдельный Cloudflare API Token для этого аккаунта: Workers Scripts Edit, D1 Edit и Account Settings Read. Используйте минимальные права на нужный аккаунт, не Global API Key.

Введите Cloudflare token через защищённые настройки среды, а Account ID — как переменную окружения. Не присылайте токены в чат, не вставляйте их в команду и не коммитьте `.env`/`.dev.vars`. Proxy-backed Cloudflare token подходит для авторизации HTTPS-запросов к `api.cloudflare.com`; сохранение требования в настройках не означает, что значение уже настроено или доступ разрешён.

После настройки из корня проекта:

```sh
npm ci
npm run cf:deploy
```

Скрипт проверяет аккаунт и настоящий workers.dev-поддомен, находит или создаёт D1 `aik-base-orders`, применяет миграции и публикует Worker `aik-base-api`. Настоящие Account ID, D1 ID и публичный URL записываются в игнорируемый `.wrangler.deploy.json`; `wrangler.jsonc` сохраняет явный локальный placeholder. Миграции не удаляют заказы, а повторные публикации сохраняют dashboard variables и secrets. Worker Secrets не записываются в этот файл.

Команда выводит настоящий адрес вида `https://aik-base-api.<ваш-поддомен>.workers.dev`. Не используйте адрес-пример как реальный endpoint.

Если Cloudflare не предоставил аккаунт, токен, поддомен или нужные права, публикация останавливается. Код, локальные тесты и `cf:check` не доказывают, что production API уже запущено.

## 2. Подключение @AikBaseOrder_Bot

В Cloudflare откройте Worker → Settings → Variables and Secrets. Задайте:

| Имя                       | Тип        | Значение                                                                                                              |
| ------------------------- | ---------- | --------------------------------------------------------------------------------------------------------------------- |
| `TELEGRAM_BOT_TOKEN`      | **Secret** | Настоящий токен вашего BotFather-бота.                                                                                |
| `TELEGRAM_WEBHOOK_SECRET` | **Secret** | Отдельная случайная строка 32–256 символов `A–Z a–z 0–9 _ -`. Например, сгенерируйте локально `openssl rand -hex 32`. |
| `PUBLIC_API_URL`          | Variable   | Настоящий HTTPS-адрес опубликованного Worker. Скрипт публикации задаёт его автоматически.                             |
| `MINI_APP_URL`            | Variable   | `https://trofimmokrov-netizen.github.io/aik-base/`                                                                    |
| `TELEGRAM_ADMIN_CHAT_ID`  | Variable   | Числовой ID **личного чата** мастера. Можно добавить после следующего шага.                                           |
| `ALLOWED_ORIGINS`         | Variable   | `https://trofimmokrov-netizen.github.io`, без пути и завершающего `/`.                                                |

Telegram token должен быть настоящим Worker Secret: Worker использует его локально для HMAC-проверки initData. Сетевой proxy placeholder не заменяет это значение. На стороне Cloudflare заполните секрет напрямую через защищённую панель. Не помещайте токен в `VITE_*`, frontend, конфигурацию Wrangler, публичный URL или GitHub Pages.

Сохраните и примените настройки. В течение минуты Cron:

1. Проверит `getMe` и точное имя `AikBaseOrder_Bot`. Токен другого бота не используется для изменения настроек или отправки данных клиентов.
2. Зарегистрирует команды `/start`, `/services`, `/order`, `/contact`, `/help`, `/id`.
3. Установит кнопку Mini App и защищённый webhook. Накопленные обновления не удаляются.

Сначала мастеру нужно открыть бота и нажать `/start`. Команда `/id` покажет ваш числовой ID. Запишите его в `TELEGRAM_ADMIN_CHAT_ID`, примените изменение. Для регистрации команд и получения `/id` администраторский ID ещё не требуется.

`GET /api/health` должен показать `status: ok`, `storage: cloudflare-d1`, `telegramRegistered: true`, `notificationsReady: true`. Регистрация Telegram подтверждает принятие настроек Bot API, а доставка конкретного уведомления подтверждается только настоящим тестовым заказом.

## 3. Включение API на сайте

Когда API и бот настроены, выполните с настоящим адресом:

```sh
npm run cf:enable -- https://aik-base-api.ВАШ-ПОДДОМЕН.workers.dev
```

Скрипт проверяет HTTPS, D1, регистрацию бота и готовность уведомлений. При ошибке статический сайт не меняется. При успехе он записывает публичный `apiUrl` в `shared/site.json` и включает серверный режим в workflow Pages. Прежняя передача `vars.VITE_API_URL` удаляется, чтобы случайная устаревшая GitHub variable не переопределила проверенный адрес. Токен в frontend не попадает.

Проверьте изменения, соберите `npm run build:server`, отправьте изменения в `main` и дождитесь успешной публикации Pages. Сам `cf:enable` не делает коммит, push или публикацию.

После публикации:

- Отправьте тестовую заявку с сайта или Mini App и сохраните номер/ключ доступа.
- Убедитесь, что мастер получил уведомление с номером, контактом, размерами и описанием. После сохранения запускается фоновая доставка; при сбое Cron повторяет её с увеличивающейся задержкой.
- Откройте «Мои заявки» и проверьте свой статус. Чужой аккаунт и неверный ключ должны получать отказ.
- В личном чате мастера выполните `/status <UUID> in_progress` или `completed` и обновите статус в приложении. Команда ограничена ID настроенного мастера.

## Локальная разработка и проверки без аккаунта

```sh
npm run cf:check
npm run test:cloudflare
npm test
```

`cf:check` — настоящая сборка Wrangler без загрузки. `test:cloudflare` создаёт отдельную временную D1, применяет миграцию и запускает локальный workerd; проверяются HTTP API, идемпотентность и сохранение заявки после перезапуска. Никакие живые Telegram-сообщения не отправляются. `npm test` дополнительно проверяет Worker SQL/криптографию, приватность, подписи, очередь, повторные попытки и административные команды с подменённым Telegram-транспортом.

Для ручной локальной разработки:

```sh
npm run cf:migrate:local
npm run cf:dev
```

Wrangler использует порт 8787 и локальное хранилище `.wrangler/`. Для секретов локально можно скопировать `.dev.vars.example` в `.dev.vars`, не перезаписывая существующий файл. Cron по умолчанию в локальной среде не запускает бота автоматически; для его намеренной проверки используется документированный Wrangler режим `--test-scheduled`. Не используйте production token для обычных тестов.

В ограниченной облачной среде с недоступным домашним каталогом задайте `XDG_CONFIG_HOME=/workspace/.cache/cloudflare`. Сохраняйте унаследованные proxy и CA; TLS-проверка должна оставаться включённой. Для публикации нужен доступ к `api.cloudflare.com`, для проверки API — к точному hostname полученного Worker. Не добавляйте произвольные `*.workers.dev` вместо известного адреса.

## Хранение и доставка

- Заявки и задания Telegram сохраняются в одной D1-транзакции. Конкурентная повторная отправка создаёт один заказ и одно задание.
- Ключи доступа хранятся в виде SHA-256-хешей. Владелец Mini App определяется только по серверной HMAC-проверке initData с ограничением времени.
- Webhook требует отдельного секрета; дубли `update_id` не повторяют изменение статуса или ответ. Обновление и его эффекты фиксируются атомарно.
- D1-ограничители запросов действуют между экземплярами Worker. IP для bucket хранится хешированным.
- Задания забираются атомарно с временной блокировкой. При прерванном выполнении они становятся доступны снова; доставка Telegram — минимум один раз, поэтому после сетевого сбоя возможен дубль сообщения с тем же номером заявки.
- Обычные webhook-ответы содержат только `ok`. Ответы и уведомления отправляются из очереди через waitUntil сразу после сохранения; Cron подхватывает отложенные и прерванные задания. Персональные данные не выводятся в логи; observability по умолчанию выключена.
- Выполненные задания, записи дедупликации старше семи дней и истёкшие rate buckets очищаются Cron. Сами заказы автоматически не удаляются: установите свои сроки хранения и удаляйте их по обращениям клиентов.

Для резервного копирования используйте D1 export/инструменты Cloudflare; экспорт содержит контакты и должен храниться вне Git. Удаление заказа администратором из D1 также удаляет связанное задание благодаря внешнему ключу; отдельно обработайте уже доставленные копии в Telegram.

Полный API совместим с существующим frontend: `/api/health`, `/api/config`, `/api/services`, `/api/estimate`, `/api/orders`, `/api/orders/:id`, `/api/my/orders`, `/api/telegram/webhook`.
