# Подключение @AikBaseOrder_Bot

Для запуска только команд на встроенном хостинге Sites, аналогично проекту Ксении и без собственного аккаунта Cloudflare, подготовлен [отдельный Fetch-обработчик](../sites/README.md). Он пока не опубликован; основная отправка заявок остаётся ручной.

Сейчас выбран статический сайт без отдельного сервера. Автоматические ответы бота, webhook и статусы не подключены. Статический интерфейс можно открыть в Telegram WebView по публичной ссылке, но отправка заявки остаётся ручной. Далее — инструкции для будущего серверного режима.

Реализованы команды `/start`, `/services`, `/order`, `/contact`, `/help`. Бот отвечает в личных чатах и открывает тот же интерфейс сайта как Mini App. Клиент оформляет заявку в форме; обычные сообщения боту не пересылаются мастеру автоматически.

## Настройка

1. Разверните backend по публичному HTTPS-адресу, обеспечьте постоянный диск для SQLite.
2. В защищённых переменных backend-хостинга задайте `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_CHAT_ID`, `MINI_APP_URL`, `PUBLIC_API_URL` и `TELEGRAM_WEBHOOK_SECRET`.
3. `TELEGRAM_ADMIN_CHAT_ID` — положительный числовой ID личного чата мастера. Мастер должен сначала открыть бота и нажать `/start`. ID можно получить из уже имеющихся доверенных данных аккаунта или из обновлений вашего бота. Не присылайте токен сторонним ботам для определения ID.
4. Сгенерируйте независимый webhook-секрет: `openssl rand -hex 32`; сохраните его через настройки хостинга.
5. Укажите точный origin сайта в `ALLOWED_ORIGINS` API, например `https://trofimmokrov-netizen.github.io` (без `/aik-base/`).
6. Из окружения с доступом к `api.telegram.org` выполните `npm run telegram:configure`. Скрипт проверит имя бота, зарегистрирует команды, кнопку Mini App и webhook. Накопленные обновления не удаляются.
7. В BotFather откройте `/mybots` → ваш бот → Bot Settings → Configure Mini App (или доступный в интерфейсе пункт Mini App) и укажите тот же HTTPS-адрес, если хотите кнопку запуска в профиле. Название и описание можно заполнить вручную: «AIK BASE — сварочные работы и металлоконструкции. Подберите услугу и отправьте заявку мастеру».

В Docker настройку можно выполнить командой `docker compose exec aik-base node scripts/configure-telegram.mjs`, используя переменные сервиса. Повторный запуск сохраняет те же команды и endpoint; токены в вывод не попадают.

## Проверка живой интеграции

- Откройте бота в личном чате, отправьте `/start`, затем `/services` и `/help`.
- Нажмите «Открыть AIK BASE». Введите тестовую заявку и согласие.
- Убедитесь, что мастер получил номер, услугу, контакт, размеры, комментарий и дату. `/api/health` показывает готовность конфигурации, но сам по себе не подтверждает доставку.
- В Mini App откройте «Мои заявки»: должна появиться собственная заявка.
- С другого Telegram-аккаунта чужая заявка не должна открываться.
- Мастер меняет статус в своём личном чате с ботом:

```text
/status <полный UUID> reviewing
/status <полный UUID> agreed
/status <полный UUID> in_progress
/status <полный UUID> completed
```

Другие допустимые статусы: `new`, `cancelled`. Команда принимается только когда ID отправителя и ID личного чата совпадают с `TELEGRAM_ADMIN_CHAT_ID`; клиентам она не даёт доступ к чужим заявкам.

## Безопасность и ограничения

API проверяет HMAC `initData`, давность `auth_date` и Telegram ID. Просроченная сессия требует повторного открытия Mini App. Не сохраняйте `initData` в логах. Webhook требует независимый секрет, повторные `update_id` не создают повторных заданий.

Если Telegram недоступен или мастер ещё не открыл бота, заказ сохраняется, уведомление остаётся в очереди и повторяется с увеличивающимся интервалом (до часа). Настройка `notificationsReady` означает наличие токена и ID, а не доказанную доставку. Ошибочные значения надо исправить в защищённых переменных и перезапустить API. Живые процессы и сетевые авторизации не сохраняются автоматически между облачными задачами.

Для Telegram нужны исходящие HTTPS-запросы к `api.telegram.org`; для загрузки SDK браузеру нужен `telegram.org`. Токен требуется Node в настоящем виде для HMAC. Proxy-only placeholder не заменяет серверное значение.
