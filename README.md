# AIK BASE — Сварка, которая держит.

Сайт для сварочных работ и металлоконструкций с интерфейсом, адаптированным для Telegram WebView. Русский язык, мобильная вёрстка, восемь услуг, галерея, калькулятор и подготовка заявки для прямой связи с мастером. Дополнительный сервер сейчас не используется; API и бот подготовлены для будущего подключения.

## Запуск без отдельного сервера

Текущий режим — **статический сайт на GitHub Pages**. Каталог, галерея, видео, калькулятор и форма подготовки текста работают без API и токенов. Сайт не отправляет заявки автоматически: посетитель копирует текст, скачивает его, открывает SMS или делится им через системное меню. Отправку и получение подтверждают участники переписки. Телефон мастера: **+7 934 999-97-79**.

Нужен **Node.js 24** для разработки и сборки:

```sh
npm ci
npm run dev
```

Откройте `http://localhost:5173/aik-base/`. Для сборки и проверки готового сайта:

```sh
npm run build
npm run preview
```

Обычная сборка без `VITE_API_URL` работает автономно. Workflow Pages явно задаёт `VITE_APP_MODE=static`, поэтому не зависит от серверных переменных репозитория. В браузерной форме данные находятся только в открытой странице и не передаются в API. «Мои заявки», серверные статусы и ссылки на неподключённого бота в этом режиме скрыты. Тарифы рассчитываются по `shared/rates.json`; пока тарифы не заданы, цена согласуется индивидуально.

Telegram SDK загружается асинхронно только при открытии внутри Telegram. Обычный сайт не ждёт `telegram.org`. В Mini App остаются доступными те же статические функции, но запущенный бот и автоматический приём заявок без backend не заявляются.

## Необязательный серверный режим на будущее

Код API и бота сохранён для последующего подключения. Для него нужны публичный HTTPS backend, постоянное хранилище и секреты. Сейчас дополнительный хостинг не требуется и не настраивается.

```sh
cp .env.example .env
npm run dev:server
# В другом терминале:
npm run dev:connected
```

`dev:connected` включает серверный режим и проксирует `/api` на порт 3001. Для сайта с API на одном домене:

```sh
npm run build:server
npm start
```

Сайт будет на `http://localhost:3001/aik-base/`, API — на `/api`. Для раздельных доменов задайте публичный `VITE_API_URL` до сборки. `VITE_APP_MODE=server` также включает интеграцию; `--mode server` в `build:server` включает её явно. SQLite входит в Node.js 24 и создаётся в `data/`. Без Telegram-настроек серверные заявки сохраняются, но уведомления ожидают настройки. В этом режиме запросы не подменяются локальным успехом.

## Что реализовано

- Восемь направлений работ, заказ из карточки, мобильное меню, якорная навигация, FAQ и контакты.
- Галерея с фильтрами, увеличением фотографий и видеоплеером. В портфолио добавлено предоставленное мастером видео лестницы, площадки и перил; иллюстрации из галереи убраны.
- Калькулятор: услуга, материал, два размера в метрах, количество и выезд. Единая формула расчёта для браузера и будущего API.
- Статическая форма с валидацией, подготовкой сообщения, копированием, TXT-файлом, SMS-ссылкой и системной кнопкой «Поделиться». Автоматической отправки нет.

В необязательном серверном режиме также реализованы лимиты запросов, идемпотентность, проверка Telegram initData и следующие функции:

- SQLite с WAL, закрытыми правами файла, постоянным хранением заказов и очередью доставки Telegram.
- Приватный просмотр заявки: личный ключ браузерной заявки или проверенная сервером Telegram-авторизация владельца.
- История до 50 последних собственных Telegram-заявок, команды бота, Mini App-кнопка, webhook с секретом и дедупликацией.
- Уведомления администратору с повторными попытками и изменение статуса через `/status` в личном чате администратора.
- GitHub Actions для проверок и публикации статического сайта, Docker и инструкция для отдельного API.

## Настройки

Публичный телефон мастера: **+7 934 999-97-79**. Он задан в `shared/site.json`, доступен на статическом сайте даже без API и используется ботом для `/contact`. `CONTACT_PHONE` на backend позволяет переопределить его. Настоящий Telegram ID администратора задаётся отдельно: телефон не заменяет `TELEGRAM_ADMIN_CHAT_ID`.

Полный список — в `.env.example`. Реальные секреты не включаются в Git, сборку, Docker-образ или браузерный код. Переменные `VITE_*` публичны: **никогда не записывайте в них токены**.

| Переменная                       | Назначение                                                                       |
| -------------------------------- | -------------------------------------------------------------------------------- |
| `VITE_APP_MODE`                  | `static` — без API, `server` — подключённый сервер. Pages использует `static`.   |
| `VITE_API_URL`                   | Публичный адрес API для будущего серверного режима. Сейчас оставьте пустым.      |
| `PORT`, `HOST`                   | Адрес прослушивания Node, по умолчанию `3001`, `0.0.0.0`.                        |
| `DATABASE_PATH`                  | SQLite на постоянном диске, по умолчанию `./data/aik-base.db`.                   |
| `ALLOWED_ORIGINS`                | Точные origin сайта, через запятую, без пути и завершающего `/`.                 |
| `TRUST_PROXY_HOPS`               | `0` напрямую; `1` только за одним доверенным reverse proxy.                      |
| `TELEGRAM_BOT_TOKEN`             | Серверный секрет BotFather; нужен также для локальной HMAC-проверки initData.    |
| `TELEGRAM_ADMIN_CHAT_ID`         | Числовой ID личного чата мастера с ботом. Мастер должен сначала нажать `/start`. |
| `TELEGRAM_WEBHOOK_SECRET`        | Независимая случайная строка 32–256 символов `A–Z a–z 0–9 _ -`.                  |
| `MINI_APP_URL`                   | Публичный HTTPS-адрес приложения.                                                |
| `PUBLIC_API_URL`                 | Публичный HTTPS-адрес API для регистрации webhook.                               |
| `CONTACT_PHONE`, `CONTACT_EMAIL` | Необязательные публичные контакты.                                               |

Токен на хостинге должен быть доступен Node как настоящее серверное значение: подстановка секретов только в сетевом прокси не подходит для локальной проверки HMAC. В облачной среде без такого механизма можно разрабатывать и тестировать с тестовыми данными; действующий секрет задайте через защищённое хранилище конечного backend-хостинга. Не публикуйте `.env` и содержимое базы.

## Проверки

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Для уже установленного Chromium: `CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e`. Статические E2E поднимают только Vite preview на порту 3002 и проверяют desktop/mobile, отсутствие API-запросов, запуск при недоступном Telegram SDK, локальный расчёт, валидацию, составление и скачивание текста, SMS-ссылку, видео и телефон.

Проверка сохранённого серверного режима отдельно:

```sh
npm run build:server
npm run test:e2e:server
# Вернуть текущий статический вариант:
npm run build
```

Серверные E2E используют API на порту 3002 с временной базой `/tmp/aik-e2e-*.db`. Рабочие заказы не затрагиваются. `npm test` проверяет HMAC, доступ к заявкам, повторные запросы, очередь, валидацию и SQLite. Живые сообщения Telegram в тестах не отправляются.

## Цены, услуги и ваши фотографии

Услуги: `shared/services.json`. Тарифы: `shared/rates.json`. При `configured: false` или отсутствии любого необходимого тарифа показывается «Стоимость рассчитывается индивидуально».

Если вы действительно используете расчёт по площади, задайте `configured: true`, ставку услуги в `servicePerSquareMeter`, множители материалов, доплату `visitFee` и, при необходимости, `minimumOrder`. Формула: `max(минимальный заказ, длина × высота × количество × ставка × множитель + выезд)`. Для работ, которые нельзя корректно считать по площади, оставьте тариф услуги незаданным. Тарифы согласует владелец; проект не содержит выдуманных цен.

Добавление фотографий:

1. Положите оптимизированные фотографии в `public/photos/` (желательно WebP, до 300 КБ на превью).
2. Добавьте записи в `src/content/portfolio.json`: `id`, `title`, `category`, `label`, `image: "photos/имя.webp"`, `position: "center"`, `demo: false`, `description`.
3. Для категорий используйте ID услуги: например `welding`, `canopies`, `structures`, `stairs` или `gates`. Кнопки фильтров создаются автоматически из записей галереи.
4. Для видео добавьте необязательное поле `video: "media/имя.mp4"`, а в `image` укажите превью. Видео загружается по открытию, проигрывается с управлением и без автоматического запуска. Маркировка карточек и просмотра учитывает `demo` и тип материала.
5. Не публикуйте лица, номера, адреса и фотографии объектов без разрешения владельцев.

`public/workshop.svg` в оформлении главной страницы — графическая иллюстрация. В портфолио используется реальное видео, предоставленное мастером: `public/media/staircase-platform.mp4` и его превью. Ролик оптимизирован для сайта, исходник не изменён; аудио сохранено. Четыре изображения из сообщения ещё нужно передать исходными JPG/PNG/WebP-файлами для добавления в репозиторий.

## Развёртывание

См. [docs/deployment.md](docs/deployment.md). GitHub Pages публикует **только фронтенд**; API, SQLite и webhook должны работать на отдельном сервере с постоянным диском. Можно разместить весь проект на одном VPS. Наличие workflow-файла не означает, что Pages уже включён или сайт опубликован.

## API (не используется текущим статическим сайтом)

| Метод | Путь                    | Доступ                                                                    |
| ----- | ----------------------- | ------------------------------------------------------------------------- |
| GET   | `/api/health`           | Проверка базы и статуса конфигурации                                      |
| GET   | `/api/config`           | Только публичные контакты и признаки подключения                          |
| GET   | `/api/services`         | Каталог                                                                   |
| POST  | `/api/estimate`         | Параметры калькулятора                                                    |
| POST  | `/api/orders`           | JSON заявки, заголовок `Idempotency-Key: <UUID>`                          |
| GET   | `/api/orders/:id`       | `Authorization: Bearer <личный ключ>` или `Authorization: tma <initData>` |
| GET   | `/api/my/orders`        | Только `Authorization: tma <initData>`                                    |
| POST  | `/api/telegram/webhook` | `X-Telegram-Bot-Api-Secret-Token`                                         |

`POST /api/orders` принимает `serviceId`, `metal` (`steel`, `stainless`, `aluminum`), `width`, `height`, `quantity`, `onsite`, `name`, `contact`, `description`, `comment`, `consent: true`, `website: ""`. Клиент не может назначить владельца, статус, итоговую цену или Telegram ID. `initData` проверяется HMAC-SHA256 и принимается не более часа; после истечения откройте Mini App заново. Не используйте `initDataUnsafe` для авторизации.

Для браузера личный ключ хранится в `sessionStorage`, только до закрытия вкладки. На экране успеха можно скачать JSON-файл с номером и ключом: сохраните его в личном месте и используйте поле «Личный ключ доступа» для восстановления доступа в новой вкладке. Не передавайте файл другим людям. Ключ не передаётся в URL. Ключи доступа в базе сохраняются как хеши. Авторизованные Telegram-заявки доступны владельцу при следующем открытии приложения. SQLite не шифрует данные самостоятельно: защитите диск и резервные копии средствами хостинга.

## Перед публичным приёмом заказов

Укажите реквизиты исполнителя, публичный контакт, правила и сроки хранения данных; согласуйте реальную географию, сроки и тарифы. В текущем интерфейсе нет выдуманных отзывов, выполненных заказов, гарантий, адресов или цен. Информационный текст о данных нужно адаптировать под фактического исполнителя и применимые требования.

Это один экземпляр Node с SQLite и очередью доставки минимум один раз: при сетевом обрыве после доставки Telegram может повторить уведомление; номер заявки помогает отличать дубликаты. Для нескольких реплик перенесите хранилище и очередь в общую БД. Приём платежей и загрузка клиентских файлов в текущую версию не входят.

Удаление заявки по обращению клиента на доверенном сервере:

```sh
node --env-file-if-exists=.env scripts/orders.mjs delete <UUID>
```

Отдельно обработайте копии уведомлений в Telegram и резервные копии согласно установленным срокам хранения. Для резервного копирования работающей SQLite используйте SQLite Online Backup (`sqlite3 data/aik-base.db ".backup '/защищённый/путь/backup.db'"`), а не копирование только `.db` при активном WAL. Проверьте восстановление на отдельном файле.
